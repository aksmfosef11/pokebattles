## 읽을 때 주의

1. **규칙이 시기마다 다릅니다.** 패치마다 서버 빌드가 바뀌고, `all.*`은 그 전부를 합친 값이라 최근 규칙의 밸런스를 보여 주지 않습니다.
   패치 전후는 `build-*.md`끼리 비교하세요. 빌드 이름은 서버 코드가 바뀐 배포마다 새로 생기는 해시라서 `git log`의 커밋 시각과 맞춰 봐야 합니다.
   - `11fa19fcac`은 커밋 `bb61e8b`(10-05 피카츄 볼트태클) 배포 직후부터,
   - `d62715d5d0`은 커밋 `24c8af5`(10-15 밸패, 이 저장소의 마지막 커밋) 배포 직후부터 시작합니다.
   - `2b15b34f31`(10-30~)에 해당하는 커밋은 저장소에 없습니다. 위와 같은 코드를 다시 배포했을 수도 있고 아닐 수도 있어서, 표본도 적으니(124판) 참고만 하세요.
2. **사람마다 실력 차이가 큽니다.** 한 사람이 200판 넘게 한 경우도 있습니다. 같은 사람의 홀수 판과 짝수 판 성적의 상관이 0.49라서(0이면 운, 1이면 실력),
   결과의 상당 부분이 챔피언이 아니라 플레이어 실력입니다. 챔피언을 고르는 사람의 성향도 섞여 있습니다.
3. **포켓몬·도구 승률은 원인이 아닙니다.** 센 구성은 숙련자가 고르는 경향이 있어서, 승률이 높다고 그 자체가 강한 것은 아닙니다. 선택률과 같이 보세요.
4. 전투 승률의 표본이 수백 회 아래면 ±5%p는 우연으로 흔들립니다.

1. 챔피언 표에서 평균 승수·클리어율이 튀는 챔피언을 찾습니다. 전 기간 기준으로는 성호(steven)가 평균 5.01승으로 가장 높고
   목호(lance)가 3.72승·클리어 12.2%로 가장 낮습니다 (`all.md`의 Champions 표). 최근 빌드에서도 같은지 `build-*.md`로 확인하세요.
2. 규칙은 `packages/game/src/content/champions.ts`(챔피언 규칙, 초반 보정), `packages/game/src/content/items.ts`(도구), `packages/game/src/run/`(상점·진행)에 있습니다. 설계 의도는 [docs/DESIGN.md](../../docs/DESIGN.md) §6.
3. 고친 뒤에는 봇 시뮬레이션으로 확인합니다: `pnpm balance --quick --fast`(약 2분), 자세한 목표(봇 런 중앙값 40~60% 등)는 DESIGN.md §6.
   봇은 사람처럼 아이템을 몰아주지 못해서(예: 레드의 에이스) 봇 수치와 실제 플레이 수치가 다를 수 있으니, 이 통계와 함께 보세요.
4. 새 서버를 열어 직접 데이터를 모으려면 [README](../../README.md)의 "밸런스 통계 (실제 플레이)" 절을 따르세요 (`pnpm stats`).
